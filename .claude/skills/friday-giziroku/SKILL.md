# giziroku — 議事録生成スキル

Plaud / Teams 等の音声文字起こしファイルを入力に、**対話で前提を固めてから**、
そのまま提出できる議事録（サマリー / 論点 / 決定事項 / TODO / 保留・持ち帰り）を
1 本生成する。設計の出典: [`ideas/giziroku.md`](../../../ideas/giziroku.md)。

議事録は**提出用**（読み手は会議に出ていない第三者）として本文だけで分かる内容に閉じ、
補正の痕跡や不明点などの本人用メモは**確認メモ**（別ファイル）に分離する。

> **起動条件（重要）**: このスキルは **ユーザーが意図的に起動する**。文字起こしファイルを指して
> 議事録化を依頼されたときだけ走る。ログ収集・作業整理系の [jarvis-worklog](../jarvis-worklog/SKILL.md) とは
> **別系統**で、パイプラインを共有しない。「作業ログまとめて」では起動しない。

## 場所（コードとデータは分離）

- ツール・設定: このスキルディレクトリ `.claude/skills/friday-giziroku/`
  （`scripts/` `templates/` `references/` `config/`）
- **入力（文字起こし）**: リポジトリ直下 `giziroku/transcripts/` に置く。ユーザーが他の場所を
  指定した場合はそのパスを使う。
- **出力（議事録）**: リポジトリ直下 `giziroku/minutes/`。**1 ファイル = 1 議事録**。
  ファイル名は `YYYY-MM-DD_<会議タイトル>_議事録.md`。
- **出力（確認メモ・本人用）**: リポジトリ直下 `giziroku/notes/`。
  ファイル名は `YYYY-MM-DD_<会議タイトル>_確認メモ.md`（[`templates/notes.md`](templates/notes.md)）。
  誤変換の補正メモ・不明点/要確認・元文字起こしファイル名は議事録に入れず、必ずこちらに書く。
- **処理済みの入力**: 議事録生成に成功したら、入力ファイルを `giziroku/transcripts/` から
  `giziroku/processed/` へ**移動して退避**する（削除はしない＝原文を残す）。これで
  `transcripts/` には未処理分だけが残り、処理済み/未処理が区別できる。
- `giziroku/` は機密を含みうるため **git 管理外**（`.gitignore` 済み）。
- 自己進化資産（誤変換辞書・参加者名簿）は **2 層**で持つ:
  - 同梱の雛形（git 追跡・機密なし）: `config/glossary.example.yaml` / `config/roster.example.yaml`（汎用シード）
  - 実データ（**git 管理外**・蓄積先）: `giziroku/config/glossary.yaml` / `giziroku/config/roster.yaml`
    （顧客名・人名など機密を含みうるため `giziroku/` 配下に置く。無ければ雛形をコピーして初期化）。
  - 読み込みは雛形＋実データをマージし、**追記（自己進化）は必ず実データ側 `giziroku/config/`** に行う。
  - ★プロジェクト横断で共有・蓄積（使うほど誤変換補正と話者推定が当たるようになる）。

## トリガーと非トリガー

| 起動する発話の例 | 起動しない（誤起動を避ける）|
|---|---|
| 「この文字起こしから議事録作って」 | 「今日の作業まとめて」→ worklog |
| 「`...-transcript.txt` を議事録にして」 | 「技術整理して」→ worklog / knowledge-base |
| 「Plaud の書き起こし、決定事項と TODO 抜いて」 | 「進捗報告して」→ worklog |
| 「エージェントとの電話の文字起こし、要点まとめて」 | （ファイル指定の無い雑な要約依頼）|
| 「雑談ログだけど決まったことだけ拾って」 | （人となり・話題の記録が目的）→ 対象外（onclimb-cabin の vision-people-memory） |
| 「立ち話で決まったこと、メモに残して」 | |
| 「Teams の文字起こし、参加者だけ確認してから議事録化」 | |

## 4 段フロー（この順序は固定。崩さない）

「**対話で前提を固める → 機械的に下処理 → 構造抽出 → 下書き → 不明点の確認 → 清書**」。
最初の対話で匿名話者・種別の不確実性を入口で潰し、清書前の確認で推測補正・不明点を潰す。

### Phase A. 一次パース（機械処理）

1. 対象ファイルパスを受け取る（未指定なら `giziroku/transcripts/` の中身を `ls` で提示し選ばせる）。
2. 解析スクリプトを実行して素材（話者集計・抜粋・タイムライン・分離有無）を得る:
   ```bash
   python3 .claude/skills/friday-giziroku/scripts/parse_transcript.py "<transcript_path>" --json
   ```
   - `diarization: labeled` → 話者ラベルあり（`Speaker N` 等）。
   - `diarization: estimated` → 話者分離なし。スクリプトが暫定話者（`推定話者A/B…`）を割った。
     **推定であることを必ず Phase B で確認**する。
   - `timeline` は全セグメントではなく **5 分バケットの粗い索引**（時刻なしはセグメント 10 件ごと、
     最大 40 ブロック）。各ブロックは `{time, speakers, preview(代表発言1件)}`。
3. 各話者の `excerpts`（特徴的発言）と発言量から、役割の当たりを付ける（確定はしない）。
   例: BM 脆弱性診断・CloudFront 設定に言及 → 実装担当らしい。

### Phase B. 対話で前提確定（このスキルの核）★

[`references/dialogue_flow.md`](references/dialogue_flow.md) の確認 4 点を `AskUserQuestion` で確認する。
**確認は 4 点に絞る**（質問過多での離脱を防ぐ）。推定値を初期選択にする。

1. **種別**: 会議 / 相談 / 雑談 の 3 択（出力テンプレを切り替える。これ以外の種別を増やさない）。
2. **参加者マッピング**: 話者ごとに「発言量＋抜粋」を提示し、`giziroku/config/roster.yaml` の候補＋自由入力で
   「Speaker 1 はどなた？」を確認。匿名のままで良い話者は「匿名のまま」を許可。
   話者分離を推定した場合は「この切り分けで合っているか」も併せて確認する。
   役割は roster の補助情報として蓄積してよいが、**議事録の参加者欄には名前のみ**を書く。
3. **公開範囲**: internal / external / unknown。**unknown は安全側で external 扱い**（マスキング ON）。
4. **会議の目的**: 文字起こしから推定した目的案を提示し、補正してもらう。

### Phase C. 下処理（ルール確定 + 推測痕跡）

Phase C では**適用ルールを確定するだけ**で、中間ファイルとして清書 transcript を生成しない。
補正・マスキング・話者置換は **Phase D で書き出す議事録の文面にのみ適用**する
（原文は `processed/` への退避まで無改変のまま残す）。

1. **誤変換の正規化**: `giziroku/config/glossary.yaml`（無ければ同梱 `config/glossary.example.yaml` をコピーして初期化）と文脈で固有語・専門語を補正する。
   補正は議事録本文に痕跡を残さず、**確認メモ**（`giziroku/notes/`）に `元表記 → 補正` で列挙（推測を明示）。
   音声認識特有の音写崩れ（サービス名・技術用語・業界用語・人名のカタカナ化、
   同音異義語への誤変換）を glossary と文脈から漏れなく拾うこと。
2. **マスキング**: 公開範囲が external / unknown なら、実名・顧客名・固有名を `<REDACTED:種別>` 化する。
   種別と規約は [`references/masking.md`](references/masking.md)（worklog の規約を流用）。
3. **話者置換**: 確定した参加者名/役割で `Speaker N` / `推定話者X` を置換する。匿名指定は「匿名」のまま。

### Phase D. 構造抽出と議事録生成

1. [`references/extraction.md`](references/extraction.md) の判定基準で構造を抽出する:
   - サマリー（3〜5 行）/ **論点**（論点ごとに「話したこと / 決まったこと / 決まっていないこと」）
   - **決定事項**（明示的に合意されたもののみ）/ **保留・持ち帰り**（決めきれていない論点）
   - **TODO**（担当者・期日付き。不明は `担当: 不明` `期日: 未定` と明示。空欄禁止）
   - 原文が 3 万字を超える場合は一度に読み込まず、`Read` を offset/limit で分割し、
     Phase A の `timeline`（5 分バケット）を索引にして該当区間を辿る。
2. 種別に応じたテンプレで組み立てる:
   - 会議 / 相談 → [`templates/meeting.md`](templates/meeting.md)
     （サマリー → 論点 → 決定事項 → TODO → 保留・持ち帰り。この順序は固定）
   - 雑談 → [`templates/chat.md`](templates/chat.md)
   - **整形規則（全テンプレ共通）**: 改行は句読点など文章の切れ目に入れる（原則 1 文 1 行）。
     段落内で文を改行するときは文末に行末スペース 2 つ（ハードブレイク）を付け、
     `【話したこと】` 等の【】ラベルの直後は空行を入れる（Markdown ビューワーで改行が潰れないように）。
   - 地の文（サマリー・論点の要約部分）にだけ、[`personas/writing-style.md`](../../../personas/writing-style.md)
     の NG のうち **構造宣言・節末要約癖・逃げ文句**を適用する。発言の引用・決定事項・TODO の文言は
     事実性優先で言い換えない（議事録の適用は最小限に留める）。
3. **下書きと確認メモの作成**: 議事録の**下書き**を `giziroku/minutes/YYYY-MM-DD_<会議タイトル>_議事録.md` に
   **1 ファイル 1 議事録**で書き出す。同一会議の分割録音は 1 議事録に束ねる。別会議をまたいだ結合はしない。
   日付はファイル名・先頭メタ・タイムスタンプから採る。採れない場合は Phase B の
   確認バッチで確定した会議日を使う（**当日日付で埋めない**。[`references/dialogue_flow.md`](references/dialogue_flow.md)）。
   あわせて**確認メモ**を `giziroku/notes/YYYY-MM-DD_<会議タイトル>_確認メモ.md` に書き出す
   （[`templates/notes.md`](templates/notes.md)。補正メモ・不明点/要確認・元文字起こしファイル名・
   話者統合などの判断を記録する。議事録本文にはこれらを一切入れない）。
4. **不明点の確認 → 清書 ★**: 確認メモの「推測・要確認」項目をユーザーに確認してから確定させる。
   - 確認するのは、誤変換の推測補正（`（推測）`『（推測・要確認）` を付けたもの）と、
     論点・決定事項・TODO の記述に影響しうる解釈（固有名の指す対象・比喩か実在かの別 等）。
   - **内容に影響する項目を優先して質問を絞る**（`AskUserQuestion`。些末な表記ゆれで質問を増やさない）。
   - 確認結果を下書きに反映して**清書**し、確定版の議事録とする。確認メモの該当項目も
     「→ 確認済み: <結果>」の形で解決済みに更新する。
   - 確定した誤変換・固有名は `giziroku/config/glossary.yaml` へ、話者は `roster.yaml` へ追記する（自己進化）。
   - ユーザーの応答が得られない場合は下書きのまま止め、冒頭に `<!-- DRAFT: 清書前 -->` を残す
     （沈黙を確定と解釈しない）。
5. **完了判定**: 決定事項・TODO が 0 件のときは「抽出失敗」ではなく
   「雑談主体で決定/TODO なし」と判断根拠を添えて明示する（空欄で終わらせない）。
   元文字起こしのファイル名は確認メモ側に記録する（後で原文を辿れるように）。
6. **入力の退避**: 清書（確定版）まで完了したら、入力ファイルを退避する（削除しない）:
   ```bash
   mkdir -p giziroku/processed && mv "<transcript_path>" giziroku/processed/
   ```
   - `transcripts/` 以外を直接指定された入力は、ユーザーに退避してよいか一度確認する
     （勝手に他所のファイルを動かさない）。
   - 同名ファイルが `processed/` に既にあれば上書きせず、ファイル名に連番/日付を付ける。
7. 出力後、チャットに要約（参加者・決定数・TODO 数・出力パス・退避先）を返す。
8. **ToDo 台帳への収穫**（jarvis-todo-management との連携）: 議事録の TODO のうち
   **ユーザー本人が担当のものだけ**を候補として提示し、確認のうえ
   `todo.py add --status inbox --source-type giziroku --source-ref <議事録パス>` で台帳に入れる
   （追記のたびに一言通知）。他人の TODO は台帳に入れない。議事録の TODO 文言は言い換えない。
   台帳が無い環境ではスキップしてよい。

## 自己進化（実行ごとに資産が育つ）

固定する芯は崩さない（起動条件・4 段フロー・決定/保留/TODO の分離）。蓄積するのは資産:

- ユーザーが確定した参加者マッピング → `giziroku/config/roster.yaml` に追記（横断共有、次回の候補に使う）。
- ユーザーが訂正した誤変換 → `giziroku/config/glossary.yaml` に追記（横断共有、補正精度が上がる）。
- どの確認質問が毎回不要だったかは、運用しながら Phase B の初期推定を強める材料にする。

実データ（`giziroku/config/`）は固有名（機密）を含みうるため **git 管理外**で運用する。
同梱の `config/*.example.yaml` は汎用シードのみ（機密なし）で git 追跡してよい。

## やってはいけないこと

- 自動起動しない。明示依頼が無ければ走らない。
- Phase B を飛ばして生成しない。`Speaker N` / `推定話者X` を出力に残さない（匿名指定を除く）。
- 議事録本文に本人用メモを混ぜない（補正メモ・不明点/要確認・話者分離の経緯・元文字起こし名は
  確認メモへ。議事録は提出用として本文だけで完結させる）。
- 誤変換を勝手に直しっぱなしにしない（必ず確認メモに `元 → 補正` を残す）。
- 公開範囲 unknown のままマスキングを省かない（安全側で external 扱い）。
- 決定と「言いさし・アイデア」を混同しない（合意のみ決定、仮は保留へ）。
- 発言・決定事項の文言を「文章として良くする」ために言い換えない（AI 感除去の対象は地の文のみ）。
